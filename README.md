# 日計表システム（Next.js）

飲食店の日計表（売上・来客・経費・人件費の管理）を Next.js（App Router + TypeScript）で作ったものです。

## 起動

```bash
npm install
npm run dev     # http://localhost:3000
npm run build && npm start
```

Node.js 18.18 以上が必要です。

## 構成

| ファイル | 内容 |
|---|---|
| `lib/logic.ts` | 目標の配分、売上・経費・人件費の計算、取引先名の類似チェックなど（画面に依存しない） |
| `lib/useStore.ts` | 状態を `localStorage` に保存するフック |
| `lib/seed.ts` | 元のExcelの2026年11月の入力データ |
| `components/App.tsx` | 画面全体と、ダイアログの開閉 |
| `components/Summary.tsx` | 売上・来客・客単価の領域と、月間サマリー |
| `components/Pies.tsx` | 取引先の分類別の円グラフ（食材・飲料） |
| `components/Monthly.tsx` | 固定費・光熱費・広告費の月額入力 |
| `components/Settings.tsx` | 月の設定・勤務形態の設定（クリックで開閉） |
| `components/DayTable.tsx` | 日計表（日付が横、取引先・社員がまとまった行） |
| `components/NumInput.tsx` | 数値入力（全角→半角の変換、数字以外はアラート）と画面内のアラート |
| `components/VendorName.tsx` | 取引先名・氏名の表示（枠に合わせて文字を自動で縮小）と、編集・並び替えボタン |
| `components/Fold.tsx` | タイトルのクリックで開閉する枠 |
| `components/Dialogs.tsx` | 取引先・社員/アルバイト・パスワードのダイアログ |

## 注意

- データは各自のブラウザの `localStorage` に保存されます。複数の端末・スタッフで共有するには、
  データベースとAPI（Route Handlers）への置き換えが必要です。`lib/useStore.ts` の読み書きの部分が差し替え箇所です。
- 編集用パスワードの確認はブラウザ内だけで行う簡易的なものです。給与を扱う場合は、
  サーバー側の認証（ログイン）に置き換えてください。

## Vercel にデプロイする

1. このフォルダを GitHub などのリポジトリに push します（`node_modules`、`.next` は `.gitignore` で除外済み）。
2. Vercel で **Add New → Project** を選び、リポジトリを Import します。
   Framework Preset は **Next.js** が自動で選ばれます。Build Command などは変更不要です。
3. **Deploy** を押します。環境変数は設定しなくても動きます。

コマンドで行う場合は、`npx vercel`（プレビュー）、`npx vercel --prod`（本番）です。

### 環境変数（任意）

| 名前 | 内容 |
|---|---|
| `NEXT_PUBLIC_USE_SEED` | `true` にすると、本番でも元のExcelの2026年11月のデータ（`lib/seed.ts`）を入れた状態で始めます。**未設定なら本番では空の状態で、seedのデータは公開されるJavaScriptに含まれません。**開発（`npm run dev`）では常に入ります。 |
| `NEXT_PUBLIC_STORE_KEY` | ブラウザへの保存に使うキー名。初期値は `nikkei-hyo-next-v1`。 |

`NEXT_PUBLIC_` の付いた環境変数は、ビルド時にコードへ埋め込まれます。変更したら再デプロイしてください。

### 公開するときの注意

- URLを知っている人は誰でも開けます。社内用なので、検索には出ないようにしています（`noindex`）。
  限定するには、Vercelの Deployment Protection（Vercel Authentication、有料プランではパスワード保護）を使ってください。
- データは各自のブラウザにだけ保存されます。サーバーには送られないので、端末やスタッフ間では共有されません。
- 編集用パスワードも、ブラウザ内の簡易な確認です。給与を扱う場合は、サーバー側の認証に置き換えてください。

## 共有データベース（Vercel の Redis）で全員が同じデータを見る

入力した値を Redis に保存し、複数のユーザー・端末で同じデータを見られます。Redis に接続しない場合は、これまでどおり各自のブラウザだけに保存されます。

### 設定手順

1. Vercel のプロジェクトで **Storage → Create Database** を開き、**Upstash Redis**（Marketplace）を作成して、このプロジェクトに接続します。
   接続すると、環境変数 `KV_REST_API_URL` と `KV_REST_API_TOKEN` が自動で入ります（`UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN` でも動きます）。
2. **Settings → Environment Variables** に `ACCESS_CODE` を追加し、全員で共有するアクセスコードを入れます。
   本番では、`ACCESS_CODE` が未設定のあいだは、データを守るためAPIを使えません（画面には「ACCESS_CODE が未設定です」と出て、この端末だけに保存されます）。
3. 再デプロイします。最初に開いたとき、アクセスコードの入力が出ます。入力したコードは、その端末に記憶されます。

ローカルで試すときは、`vercel env pull .env.local` で環境変数を取り込んでから `npm run dev` を実行します。

### 動き

- 保存の単位は「設定」と「1か月分」です。入力が止まって0.7秒後に、変更のあった単位だけを保存します。
- 画面の上に、保存状態が出ます（保存中、共有データに保存済み、この端末だけに保存、など）。
- 他のユーザーの更新は、60秒ごと・タブに戻ったときに取り込みます（間隔は `NEXT_PUBLIC_SYNC_INTERVAL` のミリ秒で変えられます）。
- 同じ月を同時に編集して、先に他の人が保存していた場合は、先に保存された内容を残し、後の人の画面を最新に更新して知らせます。
  後の人の直前の入力は反映されないので、もう一度入力してください。
- 初めて接続したとき、サーバーが空なら、そのとき開いた端末のデータが最初のデータとして保存されます。
  すでにサーバーにデータがあるときは、サーバーの内容が使われます（ほかの端末にだけ残っているデータは取り込まれません）。
- 対象月の選択は、端末ごとです（共有しません）。

### 通信量の目安

Upstash Redis の無料枠は、1日あたり約1万コマンドです。確認のたびに約2コマンドを使うため、60秒ごとの確認で、1人が10時間開いても約1,200コマンドです。保存のたびにも数コマンドを使います。

### セキュリティの注意

- アクセスコードを知っている人は、給与・時給を含むすべてのデータを、通信の内容から読めます。「詳細情報表示」のパスワードは、画面で隠すだけの簡易なものです。給与を扱う場合は、サーバー側の権限分け（ログインと、給与を返さないAPI）が必要です。
- アクセスコードの入力に、回数の制限はありません。必要なら、Vercel の Firewall でAPIへのアクセスを制限してください。
- Redis のトークンはサーバー側（APIルート）だけで使い、ブラウザには渡しません。
